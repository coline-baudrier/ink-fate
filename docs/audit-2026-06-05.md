# Audit du projet - 5 juin 2026

Cette note capture l'etat local observe pendant la revue. Elle complete la documentation durable sans remplacer la roadmap.

## Perimetre verifie

- structure du backend, du frontend, des donnees et des tests ;
- points d'entree CLI, FastAPI et React/Vite ;
- commandes d'installation et de lancement ;
- coherence entre README, architecture, MVP, vision, game loop et roadmap ;
- tests Python hors appels LLM ;
- lint et build du frontend.

## Resultats

Frontend :

- `npm run lint` : succes ;
- `npm run build` : succes avec Vite 8.0.16.

Backend :

- `py -m pytest -q` : 252 tests passes, 2 ignores, 2 echecs.

Les deux echecs concernent des fichiers qui avaient deja des modifications locales au debut de l'audit :

1. `test_structured_prompt_limits_scene_to_active_participants`
   attend encore la phrase `Do not describe absent NPCs as nearby`.
2. `test_remove_player_internal_state_from_narration_keeps_npc_feelings`
   montre que le filtre d'etat interne du joueur supprime aussi une phrase sur le ressenti de Dean.

Ces fichiers n'ont pas ete modifies pendant la mise a jour documentaire.

## Ecarts corriges dans la documentation

- FastAPI et React n'etaient plus des fonctionnalites futures ;
- `start.ps1`, les URLs locales et le proxy Vite n'etaient pas documentes ;
- le frontend conservait le README generique de Vite ;
- l'univers charge neuf fiches personnages, pas seulement le trio du MVP initial ;
- `scene_history` et `arc_state` sont persistants dans le world runtime ;
- la phase API/interface de la roadmap etait encore marquee comme future ;
- plusieurs champs runtime recents du world n'etaient pas listes.

## Risques et limites actuels

- l'API web utilise l'univers `off-campus` et la sauvegarde `default` en dur ;
- aucune authentification ni isolation multi-utilisateur ;
- les routes FastAPI n'ont pas de suite de tests dediee ;
- le frontend n'a pas de tests automatises ;
- le chargement initial du frontend ne gere pas explicitement une erreur reseau ;
- les ecritures JSON locales ne sont pas protegees contre plusieurs requetes concurrentes ;
- les tests LLM restent optionnels et necessitent `OPENAI_API_KEY`.
